# Team Lead Lab

Илья Гажиенко ([`@Richbanker`](https://github.com/Richbanker)) ведёт проект как тимлид. Он определяет цель, ставит задачи, даёт обратную связь и принимает результат. GitHub Actions собирает сводку из текущих Issues и pull requests три раза в день.

[Поставить задачу](https://github.com/Richbanker/team-lead-lab/issues/new/choose) · [Открытые задачи](https://github.com/Richbanker/team-lead-lab/issues?q=is%3Aissue+is%3Aopen+label%3A%22team%3Atask%22) · [Журнал сводок](https://github.com/Richbanker/team-lead-lab/issues/1)

## Как вести работу

1. Создайте Issue по форме **Цель**. Укажите ожидаемый результат и способ его измерения.
2. Разбейте цель на подзадачи через форму **Задача**. Для каждой укажите роль, ожидаемый результат и критерии приёмки. На родительском Issue добавьте их как **Sub-issues**, чтобы видеть прогресс по цели.
3. Выберите роль в Issue и добавьте `status:ready`, когда задачу можно запускать. Автоматизация Codex проверяет очередь три раза в день и берёт только открытые задачи `@Richbanker` с этой меткой. При доступном Copilot cloud agent роль также можно запустить вручную через **Assignees → Copilot**.
4. Смотрите статус в Issue. Метка `status:in-progress` означает начатую работу, `status:in-review` показывает, что PR ждёт приёмки, а `status:blocked` сопровождается причиной и вопросом к тимлиду. Сводка читает эти метки из GitHub.
5. Проверяйте PR по критериям из Issue и оставляйте решение о приёмке в ревью. После приёмки слейте PR и закройте Issue как **Completed**, если оно осталось открытым. В конце этапа отметьте в цели, какие критерии выполнены, со ссылками на принятые PR.

## Роли исполнителей

| Роль | За что отвечает |
| --- | --- |
| Product | Разбивает цель на задачи и уточняет критерии приёмки |
| UX | Проектирует сценарии, состояния интерфейса и доступность |
| Frontend | Реализует клиентскую часть |
| Backend | Реализует API, бизнес-логику и работу с данными |
| QA | Проверяет сценарии и добавляет регрессионные тесты |
| DevOps | Настраивает CI, сборку и воспроизводимые проверки |
| Docs | Ведёт документацию и инструкции |
| Review | Проверяет изменения и фиксирует конкретные замечания |

## Сводки

GitHub Actions публикует отчёты ежедневно в 09:00, 13:00 и 18:00 по Москве. В них видны открытые цели, ответственные, задачи на ревью, блокеры, открытые PR и задачи, закрытые как **Completed** за последние 24 часа. Для уведомлений можно подписаться на Issue со сводками.

Разовый отчёт можно запустить через **Actions → Сводка по задачам → Run workflow**. Повторный запуск для того же окна обновляет предыдущую сводку за этот день. Публикация выполняется от `github-actions[bot]`.

Локальная проверка на Python 3.10 и новее выполняется командой `python -B -m unittest discover -s tests -v`. Те же тесты запускает CI при изменениях и в PR.
