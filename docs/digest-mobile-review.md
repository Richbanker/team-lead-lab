# Как тимлид читает сводку на телефоне

Проверены два примера сводки при размере окна **360 × 780 px**. Примеры сформированы через `render_report` на тестовых задачах, отрисованы через GitHub Markdown в режиме GFM и открыты в Edge через Playwright. Для оформления использованы стили Markdown из [журнала сводок](https://github.com/Richbanker/team-lead-lab/issues/1). Сравнены текущий вывод и вариант со ссылками из задачи [#26](https://github.com/Richbanker/team-lead-lab/issues/26).

## Пример без блокеров и задач на ревью

```markdown
## Обеденная сводка · 26.11.2026 13:00 МСК

- Блокеры · **0**
- На ревью · **0**

Открыто задач **0** · принято за 24 часа **0** · открыто PR **0**

### Блокеры (0)

—

### На ревью (0)

—
```

## Пример с задачами и длинными заголовками

```markdown
## Обеденная сводка · 26.11.2026 13:00 МСК

- Блокеры · **1**
- На ревью · **1**

Открыто задач **3** · принято за 24 часа **0** · открыто PR **0**

### Блокеры (1)

- [#24](https://github.com/Richbanker/team-lead-lab/issues/24) Восстановить публикацию сводки после ошибки при обновлении комментария в журнале и проверить, что повторный запуск сохраняет правильное окно расписания

### На ревью (1)

- [#23](https://github.com/Richbanker/team-lead-lab/issues/23) Проверить согласованность утреннего, обеденного и вечернего расписания и подтвердить результаты проверок перед приёмкой изменения тимлидом
```

Номера в примере ведут на существующие страницы. Заголовки и статусы подобраны для испытания вёрстки.

## Сколько действий нужно

За точку входа взято начало комментария со сводкой. Прокрутка и переход по ссылке считаются отдельно.

| Сценарий | Текущий вывод | Вариант со ссылками |
| --- | --- | --- |
| Убедиться, что блокеров нет | 0 переходов. Ноль виден сверху. | 0 переходов для проверки, 1 на список блокеров при необходимости. |
| Убедиться, что задач на ревью нет | 0 переходов. Ноль виден сверху. | 0 переходов для проверки, 1 на список задач на ревью при необходимости. |
| Найти блокер при непустой очереди | 1 переход с номера задачи. Сначала нужно глазами найти строку в разделе «Блокеры». В примере раздел виден на первом экране. | 1 переход в список блокеров с верхнего счётчика или 1 переход с номера видимой задачи. |
| Найти задачу на ревью при непустой очереди | 1 переход с номера задачи. Её строка расположена ниже длинного заголовка блокера. В примере она ещё видна на первом экране. | 1 переход в список задач на ревью с верхнего счётчика или 1 переход с номера видимой задачи. |
| Найти запуски в обоих примерах | Вернуться к описанию журнала, нажать «Открыть GitHub Actions», затем выбрать запуск сводки из общего списка. Это 2 перехода после прокрутки к описанию. | 1 переход в историю конкретного workflow прямо из сводки. |

На контрольной ширине область текста занимала **328 px** после отступов. Текст в обоих примерах помещался без горизонтальной прокрутки. Каждый из двух длинных заголовков в заполненном примере занял пять строк и около 120 px по высоте. Несколько таких записей могут сместить раздел «На ревью» ниже первого экрана. Ссылка на отфильтрованный список вверху даёт доступ к задачам без пролистывания длинного блока. Ссылка на историю запусков экономит возврат к описанию журнала.

Чтобы повторить проверку, вставьте пример в редактор комментария GitHub, переключитесь на **Preview**, выставьте ширину 360 px в инструментах браузера и проверьте оба раздела. Для варианта со ссылками сравните счётчики с фильтрами `status:blocked` и `status:in-review`. Фильтр ревью исключает блокеры. Ссылка на [историю запусков](https://github.com/Richbanker/team-lead-lab/actions/workflows/team-pulse.yml) открывает нужный workflow.
